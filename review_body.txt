## Review PR #77 - feat(security): apply sandbox isolation flags

**Positive aspects:**

- 9-layer defense-in-depth: Network isolation, read-only FS, memory/CPU/PID limits, non-root user, capabilities drop, seccomp - all per PRD specs
- Frozen dataclass: SandboxConfig immutable - safe for concurrent Docker operations
- isolation_layers property: Human-readable audit trail of active protections
- Docker SDK integration: get_docker_create_args() returns kwargs dict ready for docker.containers.run()
- Volume mount read-only: Binary mounted as ro - prevents tampering
- PRD reference: Every layer traced to PRD section 11.2

**Issues to fix:**

1. remove: False in get_docker_create_args (line 93): The docstring says layer 1 is "--rm" (auto-remove container) but the Docker kwargs set remove=False. The container won't auto-cleanup, causing orphaned containers. Suggestion: Set remove=True or add explicit cleanup logic.

2. Volumes key is binary_path string (line 76): Using the file path as the Docker volume source key is unconventional. Docker SDK expects {"/host/path": {"bind": "/container/path", "mode": "ro"}}. If binary_path is "/tmp/simples/programa", the key should be the directory "/tmp/simples" not the file. As written, Docker SDK may try to mount a single file. Test this edge case.

3. __pycache__ committed: backend/__pycache__/sandbox_isolation.cpython-313.pyc in the diff.

4. stdin_open + tty + detach combination: stdin_open=True and tty=True with detach=True means the container starts in background with an open stdin. The caller must use container.attach_socket() to interact. Document the expected interaction pattern for the caller.

**Suggestions (non-blocking):**

- Add no-new-privileges as a 10th layer (--security-opt=no-new-privileges)
- Consider adding --storage-opt size limit for rootfs disk usage
- Test that qemu-i386-static works with read-only rootfs (may need /dev, /proc mounts)
